## 四、重点测试场景（P0）

1. 登录并绑定一辆在线车辆，进入车辆列表，点击「远程开空调」，10 秒内状态应变为「运行中」，温度显示 24℃
2. 解绑所有车辆后进入车辆列表，点击「远程开空调」，**不应崩溃**，应提示「暂无可用车辆」
3. 断网或弱网状态下点击「远程开空调」和解锁车门，应有明确失败提示，**不能一直停在 loading**
4. 连续快速点击「远程开空调」3 次，只应下发一次有效指令，且不应崩溃
5. 登录态过期后执行车辆控制操作，应跳转登录页，登录后回到当前页面
6. 车门解锁接口返回非 200 或异常响应时，应返回失败结果并给出提示（若 UI 提示本次未实现，需在已知问题中说明），不应闪退

## 五、一般测试场景（P1 / P2）

- 切换英文、阿拉伯语，检查远程控制相关文案与布局（RTL）
- 反复进入、退出车辆列表 10 次，观察内存是否持续增长（本次改动涉及回调注册）
- 车辆列表中车辆数量为 1 辆、多辆时，点击入口的行为是否一致
- 接口返回字段缺失或类型变化时，页面是否仍可正常展示
- 冷启动后直接进入车辆列表，检查空调状态展示是否正确

## 六、风险与注意事项

- **网络层失败无回调的风险**：本次重构把失败分支改成静默返回，弱网、超时、非 JSON 响应时可能出现「一直 loading」，这是本轮重点回归项
- **车辆控制主流程**：远程空调与车门解锁都属于车辆控制，必须在真实车辆或车机模拟环境验证，不能只看接口返回
- **空列表**：车辆列表为空时入口仍可点击，存在崩溃风险，提测前需确认已修复
- **离线判断**：本次改动未包含车辆离线的前置判断，车辆离线时的表现需要测试重点确认
- **依赖项**：测试环境车辆控制网关是否可用、测试账号是否已绑定在线车辆、多语言资源是否已下发
