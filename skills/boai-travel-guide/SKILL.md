# 旅游攻略生成 — boai-travel-guide

把"周末去哪玩"变成可执行的行程：逐日时间轴 + 充电/交通方案 + 预算，交付精排版 PDF + 聊天内全文。

核心原则：**行程必须能照着走**——每个时间点真实可达（含驾驶/充电/排队缓冲），每个票价、开放时间、桩位都来自检索而非记忆。

## 执行流程概览

| 阶段 | 步骤 | 产出 |
|------|------|------|
| **1. 参数提取** | 出发地/目的地/天数/日期/交通/预算 → 缺关键参数用 AskUserQuestion 一次问清 | 行程参数清单 |
| **2. 联网调研** | WebSearch 并行搜：交通路线、充电桩（电车必查）、景点、美食、住宿、预算、贴士 | 调研笔记（含来源 URL） |
| **3. 行程编排** | 逐日时间轴，真实时间计算，⚠️ 关键时间节点 + 🚩 充电点 + 备选方案 | 完整行程表 |
| **4. PDF 交付** | 用 assets/guide_template.html 填充 → scripts/html2pdf.sh 转 PDF 到 ~/Downloads | PDF 攻略文件 |
| **5. 聊天回复** | 全文核心行程 + 预算 + 备忘 + Sources 链接 | 用户可直接出行的攻略 |

---

## 阶段 1：参数提取与确认

从用户原话提取，能推理的不要问：

| 参数 | 说明 |
|------|------|
| 出发地 / 目的地 | 必填，缺了才问 |
| 天数与日期 | 必填；**必须换算星期**（如"周五晚出发"→ 从今天日期推出具体几号星期几） |
| 交通方式 | 电车自驾 / 油车自驾 / 高铁 / 飞机；**电车自驾 → 全程启用充电规划** |
| 人数 / 预算 / 偏好 | 可默认：2 人同行、经济舒适两档都给 |

- 缺关键参数 → **AskUserQuestion 一次问清**（一个问题 2-4 个选项），不要连续追问，不要用段落问题结尾
- 用户说"**按照上次的攻略**" → 先去 `~/Downloads/*攻略*.pdf` 或会话历史找上次的攻略，**对齐它的格式、章节结构、质量水位**再开工

---

## 阶段 2：联网调研（WebSearch，可并行）

按类别逐项搜，**每条关键事实记录来源 URL**，攻略结尾必须附 Sources 链接。

| 类别 | 必查内容 |
|------|---------|
| 交通路线 | 距离 km、驾驶时长、高速路线名、高速费；高铁/飞机则查班次与耗时 |
| 🔌 充电（电车） | 沿途服务区桩位与实测功率、市区超充站、电费单价、全程充电成本对比油费 |
| 景点 | 排名与亮点、门票价格、开放时间、**闭馆日**、关键时间节点（停运/末班/亮灯/演出场次） |
| 美食 | 招牌菜、本地人认可的老店名、市场/夜市名、人均价格 |
| 住宿 | 推荐区域、价位档、电车场景下是否有充电条件 |
| 预算 | 交通/餐饮/住宿/门票各分项，汇总经济版与舒适版人均 |
| 贴士 | 季节天气、避坑提醒（收费陷阱/排队规律/淡旺季） |

**调研铁律**：
- 🚨 票价、开放时间、末班车、演出场次是**最容易过时**的信息——必须检索，检索不到就写"以官方/现场为准"，**绝不编造**，也**不凭训练记忆写具体数字**
- 🚨 里程、充电桩数量、电费单价等硬数字，尽量双来源交叉验证
- 🚨 搜索词带上「当前年份」，避免用到过期攻略的旧价格旧政策
- 记录来源时保留完整 URL，用于文末 Sources 与 PDF 末页

## 阶段 3：行程编排

### 逐日时间轴格式

```markdown
### Day 0 · 周五晚｜出发地 → 目的地（约 XX km）
| 时间 | 安排 |
|------|------|
| 18:30 | ... |
```

### 时间计算规则（行程能照走的关键）

- 高速按 **100-110 km/h** 估算驾驶时长，另加出城/进城与休整缓冲
- 电车：按 **CLTC 标称 7 折**算高速实际续航，每 200-250 km 或电量剩 30% 安排一次充电（30-45 分钟，正好吃饭休息）
- 景点按 2-3 小时节奏编排，上午户外（凉快）、正午室内（避暑）
- 周日返程必须**倒推出发时间**：确保到家不超过用户预期的晚间节点，留充电缓冲
- 每晚 22:00 前后收工，不排深夜活动

### 标记规范

- ⚠️ 关键时间节点（停运/末班/闭馆/亮灯/演出场次）必须在行程表和文末备忘中**各出现一次**
- 🚩 充电点（服务区/市区站）单独标记
- 每个关键环节给 1 个**备选方案**（满桩怎么办、天气不好换哪）

### 电车铁律（出现电车自驾时写入攻略）

1. 剩 30% 就找桩，不等报警；预留 20% 冗余
2. 充到 80-90% 就拔枪，末段充电慢
3. APP 备好：特来电 / 星星充电 / 国家电网 e充电 / 小桔，高德开「新能源模式」看实时桩位
4. 错峰：10:00-15:00 最挤；服务区排队超 30 分钟 → 下高速去出口 3-5 km 商场充
5. 出发前满电出发、胎压检查、ETC 余额

## 阶段 4：PDF 交付

1. 读取本 skill 目录 `assets/guide_template.html`，按文件内注释槽位填充内容（保留全部 CSS 与结构，只换内容）
2. 章节结构固定为七章：**封面 / 行程总览 / 景点深度榜 / 美食地图 / 住宿精选 / 费用预算 / 实用贴士**；自驾电车时在费用预算前插入**充电规划**章（模板内已带该章，非电车出行删除并重编号）
3. 🚨 设计约束：**纯 CSS 排版，禁止依赖外网图片**——很多网络环境访问不了图源，封面用模板的渐变设计即可，不要为找实景图浪费时间
4. 用 `scripts/html2pdf.sh` 转 PDF：`<skill目录>/scripts/html2pdf.sh 输出.html ~/Downloads/{目的地}攻略.pdf`
5. 校验：文件存在且非空、页数合理（5-15 页，`mdls -name kMDItemNumberOfPages` 或看文件大小）；Chrome 转完不退出是已知行为，脚本自带清理，不要手动重跑

**命名规范**：`~/Downloads/{目的地}攻略.pdf`（如 `广州柳州2日游攻略.pdf`）。

## 阶段 5：聊天回复

回复必须包含**完整核心行程**，不能只说"看 PDF"：

1. 行程总览（逐日表格全文）
2. 交通 / 充电要点（电车场景必含充电点清单）
3. 预算两档（经济版 / 舒适版人均）
4. ⚠️ 关键时间节点备忘（电梯停运时间、闭馆日、末班车这类"错过就完蛋"的信息）
5. PDF 存放路径
6. **Sources：** 调研用到的 URL 以 markdown 链接列出（WebSearch 硬性要求）

---

## 质量红线

- ❌ 编造票价、开放时间、桩位、里程、场次——查不到就标"以官方为准"
- ❌ 凭训练记忆写任何具体数字
- ❌ 只有 PDF、聊天里不给全文行程
- ❌ 攻略不含预算或只有一档预算
- ❌ 电车自驾行程缺充电规划
- ❌ 时间安排违背真实车速/充电时长，导致深夜才能到家
- ❌ 文末没有 Sources 链接
- ❌ 用户有明确称呼偏好时不遵守（参考会话记忆）
