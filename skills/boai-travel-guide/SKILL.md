# 旅游攻略生成 — boai-travel-guide

把"周末去哪玩"变成可执行的行程：逐日时间轴 + 充电/交通方案 + 预算，交付精排版 PDF + 聊天内全文。

核心原则：**行程必须能照着走**——每个时间点真实可达（含驾驶/充电/排队缓冲），每个票价、开放时间、桩位都来自检索而非记忆。

## 执行流程概览

| 阶段 | 步骤 | 产出 |
|------|------|------|
| **1. 参数提取** | 出发地/目的地/天数/日期/交通/预算 → 缺关键参数用 AskUserQuestion 一次问清 | 行程参数清单 |
| **2. 联网调研** | WebSearch 并行搜：交通路线、充电桩（电车必查）、景点、美食、住宿、预算、贴士 | 调研笔记（含来源 URL） |
| **3. 行程编排** | 逐日时间轴，真实时间计算，⚠️ 关键时间节点 + 🚩 充电点 + 备选方案 | 完整行程表 |
| **4. PDF 交付** | 用 assets/guide_template.html 填充 → scripts/html2pdf.sh 转 PDF 到 ~/Downloads | PDF 攻略文件 |
| **5. 聊天回复** | 全文核心行程 + 预算 + 备忘 + Sources 链接 | 用户可直接出行的攻略 |

## 阶段 1：参数提取与确认

从用户原话提取，能推理的不要问：

| 参数 | 说明 |
|------|------|
| 出发地 / 目的地 | 必填，缺了才问 |
| 天数与日期 | 必填；**必须换算星期**（如"周五晚出发"→ 从今天日期推出具体几号星期几） |
| 交通方式 + 车辆类型 | 见下方「交通方式确认流程」 |
| 住宿档次 + 类型 | 见下方「住宿与饮食偏好确认流程」 |
| 饮食偏好 | 见下方「住宿与饮食偏好确认流程」 |
| 人数 / 预算 / 偏好 | 可默认：2 人同行、经济舒适两档都给 |

### 交通方式确认流程

**先推断**：用户原话已明说（"开电车去""高铁过去""飞过去"）→ 直接用，不追问。

**没说才问**，用 AskUserQuestion 分两步：

1. 第一步问**通行方式**（选项：自驾（推荐）/ 高铁 / 飞机）——按里程放推荐位：单程 300 km 内自驾最划算，长途首选高铁/飞机
2. 第二步若选自驾，再问**车辆类型**（油车 / 纯电 / 混动）

> 为什么分两步：车辆类型只对自驾有意义，一步问完会让选高铁/飞机的人看到无效选项。两问都是 2-4 个选项的单次选择，不算连续追问。

### 住宿与饮食偏好确认流程

**先推断**：原话已说（"住民宿""预算 300 一晚""吃不了辣"）→ 直接用，不追问。

**没说才问**：住宿两问 + 饮食偏好一问与通行方式问题**放进同一个 AskUserQuestion 调用**一起问（该工具一次最多 4 个问题，恰好用满，一个弹窗问完，不额外打断用户）：

| 问题 | 选项（含描述） | 用途 |
|------|--------------|------|
| 住宿档次 | 经济型（约 150 元内/晚）/ 标准型（150-400/晚，推荐）/ 豪华型（400+/晚） | 决定住宿精选章的价位排序与推荐重点 |
| 住宿类型 | 连锁酒店（亚朵/全季类）/ 特色民宿（古镇/江景类）/ 高档酒店（四五星）/ 你按行程定 | 决定推荐清单的形态 |
| 饮食偏好 | 无辣不欢 / 微辣 / 忌口（可自定义输入）/ 按当地特色推荐 | 决定美食地图章的店铺选择与辣度提醒，辣味城市（湘/川渝/广西）尤其关键 |

- 每个问题都带"你按行程定"出口，用户跳过就用默认：**标准型 + 按行程位置推荐 + 按当地特色推荐**
- 档次与类型是两个正交维度（经济+民宿=平价民宿，豪华+民宿=高端民宿），组合后统一作用于住宿章节与预算章节
- 🚨 忌口用户：美食章节必须给出**替代选择**（如不吃辣 → 标注不辣菜式、不辣老店），不能只推招牌辣菜

- 其他缺关键参数 → **AskUserQuestion 一次问清**（一个问题 2-4 个选项），不要连续追问，不要用段落问题结尾
- 用户说"**按照上次的攻略**" → 先去 `~/Downloads/*攻略*.pdf` 或会话历史找上次的攻略，**对齐它的格式、章节结构、质量水位**再开工

### 交通方式 → 调研侧重对照表

交通方面的攻略**按确认后的方式做**，不要默认套自驾模板：

| 交通方式 | 交通攻略侧重 | PDF 章节处理 |
|---------|------------|------------|
| 高铁 | 车次/时刻/时长/票价、出发到达站、末班时间、市内接驳 | 交通速查表；不排充电章 |
| 飞机 | 航班时刻、机场距市区、值机安检缓冲、机场快线/接送 | 交通速查表；不排充电章 |
| 自驾 · 油车 | 路线/里程/驾驶时长/高速费、服务区油站、按油耗算油费预算 | 交通速查表；不排充电章 |
| 自驾 · 纯电 | 以上 + 沿途充电桩实测、市区超充、电费成本 | **插入完整「充电规划」章** |
| 自驾 · 混动 | 以加油为主；插混可充电 → 充电作为省钱加分项，不排强制充电点 | 充电章简化为「补能要点」小节并入实用贴士 |

## 阶段 2：联网调研（WebSearch，可并行）

按类别逐项搜，**每条关键事实记录来源 URL**，攻略结尾必须附 Sources 链接。

| 类别 | 必查内容 |
|------|---------|
| 交通路线 | 按阶段 1 确认的方式调研：自驾查距离 km/驾驶时长/高速路线名/高速费；高铁查车次时刻/票价/时长/末班；飞机查航班/机场交通 |
| 🔌 充电（纯电自驾） | 沿途服务区桩位与实测功率、市区超充站、电费单价、全程充电成本对比油费 |
| ⛽ 补能（油车/混动自驾） | 服务区油站分布、油价参考、按油耗算油费；混动标注插混可充电时的省钱玩法 |
| 景点 | 排名与亮点、门票价格、开放时间、**闭馆日**、关键时间节点（停运/末班/亮灯/演出场次） |
| 美食 | 招牌菜、本地人认可的老店名、市场/夜市名、人均价格；按饮食偏好筛选（忌口 → 备好替代选择，辣度分级标注） |
| 住宿 | 按确认的档次+类型检索对应价位的酒店/民宿清单与推荐区域；纯电自驾额外看充电条件，油车看停车条件 |
| 预算 | 交通/餐饮/住宿/门票各分项，汇总经济版与舒适版人均 |
| 贴士 | 季节天气、避坑提醒（收费陷阱/排队规律/淡旺季） |

**调研铁律**：
- 🚨 票价、开放时间、末班车、演出场次是**最容易过时**的信息——必须检索，检索不到就写"以官方/现场为准"，**绝不编造**，也**不凭训练记忆写具体数字**
- 🚨 里程、充电桩数量、电费单价等硬数字，尽量双来源交叉验证
- 🚨 搜索词带上「当前年份」，避免用到过期攻略的旧价格旧政策
- 记录来源时保留完整 URL，用于文末 Sources 与 PDF 末页

## 阶段 3：行程编排

### 逐日时间轴格式

```markdown
### Day 0 · 周五晚｜出发地 → 目的地（约 XX km）
| 时间 | 安排 |
|------|------|
| 18:30 | ... |
```

### 时间计算规则（行程能照走的关键）

- 自驾：高速按 **100-110 km/h** 估算驾驶时长，另加出城/进城与休整缓冲
- 纯电：按 **CLTC 标称 7 折**算高速实际续航，每 200-250 km 或电量剩 30% 安排一次充电（30-45 分钟，正好吃饭休息）；混动不用排强制充电点
- 高铁：提前 30 分钟到站；飞机：值机+安检预留 60-90 分钟，机场到市区接驳按时长实算
- 景点按 2-3 小时节奏编排，上午户外（凉快）、正午室内（避暑）
- 返程日必须**倒推出发时间**：确保到家不超过用户预期的晚间节点，留充电/延误缓冲
- 每晚 22:00 前后收工，不排深夜活动

### 标记规范

- ⚠️ 关键时间节点（停运/末班/闭馆/亮灯/演出场次）必须在行程表和文末备忘中**各出现一次**
- 🚩 充电点（服务区/市区站）单独标记
- 每个关键环节给 1 个**备选方案**（满桩怎么办、天气不好换哪）

### 纯电铁律（出现纯电自驾时写入攻略；混动只参考其中省钱项）

1. 剩 30% 就找桩，不等报警；预留 20% 冗余
2. 充到 80-90% 就拔枪，末段充电慢
3. APP 备好：特来电 / 星星充电 / 国家电网 e充电 / 小桔，高德开「新能源模式」看实时桩位
4. 错峰：10:00-15:00 最挤；服务区排队超 30 分钟 → 下高速去出口 3-5 km 商场充
5. 出发前满电出发、胎压检查、ETC 余额

## 阶段 4：PDF 交付

1. 读取本 skill 目录 `assets/guide_template.html`，按文件内注释槽位填充内容（保留全部 CSS 与结构，只换内容）
2. 章节结构固定为七章：**封面 / 行程总览 / 景点深度榜 / 美食地图 / 住宿精选 / 费用预算 / 实用贴士**；自驾纯电时在费用预算前插入**充电规划**章（模板内已带该章）；混动把充电内容简化为「补能要点」小节并入实用贴士；油车/高铁/飞机删除充电章并重编号。**住宿精选章按阶段 1 确认的档次+类型分档**（用户选的档放第一行标「推荐」），费用预算的两档人均与所选档次对齐——一档对齐用户选择（放前），另一档作对比
3. 🚨 设计约束：**纯 CSS 排版，禁止依赖外网图片**——很多网络环境访问不了图源，封面用模板的渐变设计即可，不要为找实景图浪费时间
4. 用 `scripts/html2pdf.sh` 转 PDF：`<skill目录>/scripts/html2pdf.sh 输出.html ~/Downloads/{目的地}攻略.pdf`
5. 校验：文件存在且非空、页数合理（5-15 页，`mdls -name kMDItemNumberOfPages` 或看文件大小）；Chrome 转完不退出是已知行为，脚本自带清理，不要手动重跑

**命名规范**：`~/Downloads/{目的地}攻略.pdf`（如 `广州柳州2日游攻略.pdf`）。

## 阶段 5：聊天回复

回复必须包含**完整核心行程**，不能只说"看 PDF"：

1. 行程总览（逐日表格全文）
2. 交通 / 充电要点（电车场景必含充电点清单）
3. 预算两档（与所选住宿档次对齐，推荐档在前）
4. ⚠️ 关键时间节点备忘（电梯停运时间、闭馆日、末班车这类"错过就完蛋"的信息）
5. PDF 存放路径
6. **Sources：** 调研用到的 URL 以 markdown 链接列出（WebSearch 硬性要求）

## 质量红线

- ❌ 编造票价、开放时间、桩位、里程、场次——查不到就标"以官方为准"
- ❌ 凭训练记忆写任何具体数字
- ❌ 只有 PDF、聊天里不给全文行程
- ❌ 攻略不含预算或只有一档预算
- ❌ 电车自驾行程缺充电规划
- ❌ 时间安排违背真实车速/充电时长，导致深夜才能到家
- ❌ 文末没有 Sources 链接
- ❌ 用户有明确称呼偏好时不遵守（参考会话记忆）

```
□ 关键参数齐全，日期已换算星期
□ 交通方式未明说时已按两步流程询问（通行方式 → 自驾再问车辆类型）

□ 交通攻略内容与确认的方式匹配（高铁查班次 / 纯电排充电 / 油车算油费 / 混动加油为主）
□ 每类信息都检索过且有来源 URL
□ 硬数字（票价/里程/桩位/场次）有检索支撑
□ 行程表含 ⚠️ 时间节点与 🚩 充电点、备选方案
□ 纯电场景已含充电规划章 + 铁律；其他方式按对照表处理充电章

□ 聊天回复含全文行程 + 两档预算 + 备忘 + Sources
□ 称呼符合用户偏好
```

## 案例参考（质量水位）

《广州柳州2日游攻略》：周五晚广州出发电车自驾 500 km，行程含去程封开服务区充电、返程马坪/大坡服务区充电，柳州市区万达小鹏超充；Day 1 青云市场嗦粉 → 龙潭公园 → 马鞍山夜景（电梯 17:00 停运、19:30 全城亮灯）→ 音乐喷泉（20:00/21:00）；Day 2 水上公交（3 元，末班 17:40）→ 伴手礼 → 14:00 返程 22:00 到家；经济版人均 850 / 舒适版 1200 元。PDF 七章 7 页，聊天同步全文 + Sources。
