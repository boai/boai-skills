# 城市美食雷达 — boai-city-food

一句话进来，直接开干：**零提问**。从用户原话提取城市名（或区名）→ 全网调研 → 综合评级 → 按区整理 → PDF + 聊天精华。

核心原则：**通用评级就是口碑**——米其林/必吃榜/非遗/老字号是硬通货，每条推荐都要能照着走（店名/地址/最推荐菜 3-5 道/人均）。

## 阶段 1：城市识别（零提问，两种模式）

- 从一句话提取城市名；处理别名与简称：羊城/花城=广州、蓉城=成都、山城=重庆、鹏城=深圳、星城=长沙、春城=昆明、冰城=哈尔滨
- 歧义时按上下文取最知名者，不追问（如「鼓楼区」→ 默认南京）
- **市级模式**：用户问「广州美食推荐」这类城市级问题
- **区级模式**：用户问「广州市花都区美食推荐」这类具体区级问题——区级单独出「前 30 家」规格，见阶段 3
- **默认口径**：按当地特色 + 大众口味；只有用户主动说「吃不了辣」「预算 X 元」才调整
- 覆盖范围：全球城市均可，国内城市优先（点评/必吃榜/非遗数据质量高）；境外城市用米其林/必比登 + 本地媒体 + 游客口碑

## 阶段 2：全网调研（WebSearch，并行）

按城市层级选权威源，**每条关键事实记录来源 URL**：

| 搜索方向 | 查询示例 | 适用 |
|---------|---------|------|
| 城市招牌菜 | 「城市名 必吃 美食 代表」 | 全部 |
| 权威榜单 | 「城市名 米其林 必比登」「城市名 黑珍珠」「城市名 必吃榜」 | 一线/新一线 |
| 官方认证 | 「城市名 非遗美食」「城市名 中华老字号 美食」「地理标志」 | 全部 |
| 菜系覆盖 | 「城市名 粤菜/川菜/湘菜/潮汕/客家/甜品 老店」逐菜系搜 | 全部 |
| 全域覆盖 | 每个行政区都搜，**远郊不能漏**（广州花都/从化/增城/番禺级），远郊以农庄/镇街老店为主；市级模式每区凑满 10 家（酌情最多 15、封顶 15），区级模式该区凑满 30 家（最低 10 家）；郊区分区成章（番禺/增城/黄埔…各一节），并搜「区名+美食+探店/博主」挖掘 B站/头条等博主渠道的宝藏店；美食大区（番禺级）还要搜官方「美食地图/十大名菜名点」并收录 | 全部 |
| 本地口碑 | 「本地人 私藏 30年老店」「街坊 口碑 避开网红店」「XX区 街坊饭堂」 | 全部 |

**调研铁律**（沿用美食推荐权重体系）：
- 🚨 价格、榜单、排队规律是最易过时的信息——必须检索，检索不到写「以门店为准」，**绝不编造**
- 🚨 「本地人最爱」需多来源反复提及，博主单次推荐不能冒充本地口碑
- 🚨 **五档分层收录，一档都不能少**：①名店老字号（陶陶居/广州酒家级）②高端食府（利苑/白天鹅级）③海鲜河鲜（黄沙市场/东江级）④连锁品质（点都德级）⑤街坊老店（惠食佳/吴财记级）——游客视角与本地视角互补，不排他、不偏科
- 🚨 **高端档必须主动检索**：搜「城市名 米其林 星级 名单 当前年份」，完整榜单中的二星/一星代表要列全（或至少列前 5），高端档不少于 5 家——不能等用户点名才发现漏了利苑
- 🚨 **必比登完整名单要全列**：已收录各章的注「散见」，未收录的补入「必比登速览」表（注意区分城市：广深合并发布时别把深圳的名单算给广州）
- 🚨 **大众点评必吃榜**：搜官方榜单（数量+分区分布）并收录；每区实时前三在点评 App 内动态更新，公开检索拿不到准确名次——注明「App 内查看」，**绝不编造名次**
- 🚨 **本地人点名的品牌必须检索验证并收录**：榜单检索可能漏掉本地知名品牌（椰林海鲜码头/花胶鸡品类级）——用户提及的品牌用「品牌名+门店」直接搜，能验证就收录
- 🚨 **特色品类必须覆盖**：城市小众特色品类（广州牛三星/牛杂/咸煎饼/猪杂粥级）要单列或带代表，不能只写大类（早茶/粤菜/川湘这种）；**火锅打边炉、烤肉烧烤必须作为独立品类覆盖**，不要漏
- 🚨 **权威标签双来源交叉验证**：米其林/必吃榜/非遗/老字号等硬标签都要 ≥2 个独立来源印证，且**注明榜单年份**——单个来源或来源可疑时不挂
- 🚨 **全球榜单维度主动检索**：搜「城市名 World's 50 Best」「Asia's 50 Best」「La Liste」——国际榜单上榜店（多为境外城市）必须收录；「米其林绿星」单独检索，与星级并列
- 🚨 **国内榜单维度主动检索**：搜「中国烹饪协会 名菜 名宴 名店」；**高德指南扫街榜/城市榜**与**大众点评好评榜/热榜/口味榜**也要检索收录（高德/点评 App 内榜单公开检索拿不到完整名单时，注明「App 内查看」）；点评店铺评分 ≥4.8 且评价量充足的挂「点评高分」徽章
- 🚨 **数据源铁律（用户指令 2026-09-08）**：字段级数据（电话/营业时间/评分/排队规律）**不用携程（ctrip）数据**——携程评分不采信、携程署名不标注、ctrip 链接不进 sources；评分口径只认大众点评/高德等来源；已有的携程残留数据在生成前用 `clean_ctrip.py` 清理
- 🚨 **官方认证维度主动检索**：老字号要查「商务部第几批」；非遗查「联合国教科文组织人类非遗」与地方名录核对级别；食品卫生等级以门店公示为准、检索不到不挂
- 🚨 **人物维度主动检索**：名店搜「店名 主厨/传承人」——名厨大师工作室、非遗传承人名录是权威背书的一部分
- 权威标签有什么挂什么，不硬凑（小城市没有米其林就不挂）
- 记录完整 URL 用于文末 Sources

## 阶段 3：综合评级与分区整理

### 综合评级规则（排序的唯一依据）

评级优先看**餐饮通用评级**，权重从高到低：

米其林星级 > 必比登推介 > 大众点评必吃榜 > 黑珍珠 > 中华老字号 > 非遗（国家级/省级/市级/区级）> 本地口碑

- 同一区内按此权重排座次；跨区无横向比较，各区内部排序
- 上榜名额固定，宁缺毋滥：**总榜只有 10 名**，每区只有 10 名（酌情可到 15，**封顶 15**）
- 4 档徽章（米其林/必比登/必吃榜/黑珍珠）是最硬的排序依据，非遗/老字号次之，口碑类只做平局裁决

### 市级模式：文档结构（主线按区）

1. **① 城市总榜 TOP 10**——先从每区「最牛的前三」做数据参考（综合评级最高的 3 家），全市合起来评比出**综合最高的十名**。总榜只写 10 家，多一家都不写
2. **② 分区详解**——**按区组织**（越秀/荔湾/天河/海珠/白云/黄埔/番禺/增城/从化/花都/南沙…），每区一节：
   - 区名 + 一句该区美食气质
   - **每区前 10 名**；该区好店确实多的酌情到 15 家，**最多 15 家**，超出的一律不进榜
   - 每区开头可放「本区前三」小摘要（该区综合评级最高的 3 家）
3. 每家店必须标注：**主营品类**（粤菜/川菜/火锅/烧烤/早茶/糖水…品类徽章）+ 店名 + 地址 + **最推荐菜（最低 3 道、最多 5 道，菜名+价格）** + 人均消费 + 权威标签
4. 必比登完整名单照旧附「必比登速览」表；城市级招牌菜（广州早茶/啫啫煲/烧鹅）进总榜，具体店分到各区

### 区级模式：文档结构（如「广州市花都区美食推荐」）

- 该区单独出**前 30 家**；实在凑不够的，**最低也要有 10 家**
- 同样按综合评级排序，每家标注：主营品类 + 店名 + 地址 + 最推荐菜 3-5 道 + **人均消费** + **餐饮标签**（权威徽章）
- 区级模式不放城市总榜，直接全区榜单 + 实用贴士 + Sources

### 每条推荐必须包含的结构化信息（最全记录表 11 字段）

1. **店名**——中文名 + 拼音/英文（双语，国际客友好）；曾用名注明「原 XX」
2. **地址**——商圈/街道级 + 导航关键词 + **最近地铁站**（门牌号易过时）
3. **联系与营业**——电话、营业时间、休息日、订位方式；查不到写「致电确认/以门店为准」
4. **主营品类**——粤菜/川菜/火锅/烧烤/早茶/糖水…（品类徽章 + 档位徽章）
5. **最推荐菜 + 价格**——**最低 3 道、最多 5 道**，每道带单品价格；查不到写「以门店为准」
6. **一菜一故事**——招牌菜的典故/来历一句话（检索到才写，不编故事）
7. **人均消费**——检索或按招牌菜推算（标注约）+ **价格带**（¥30 以下/30-80/80-150/150-300/300-800/800+）
8. **徽章分层**——国际榜单 / 国内榜单 / 官方认证 / 口碑背书四层，每层 ≤3、合计 ≤6，带榜单年份
9. **场景标签**——江景/园林/祠堂/街坊/宴请/宵夜/亲子/游客打卡（有依据才标，最多 3 个）
10. **排队指数**——等位时长、能否线上取号、建议到店时间、售罄规律
11. **人物与数据时效**——主厨/传承人（检索到才写）；检索月份 + 来源 URL ≥2（权威标签双来源交叉验证）

**使用规则**：
- 徽章**分层展示、每层 ≤3 枚、合计 ≤6 枚**；同一品牌榜单不重复挂（米其林星级与米其林入选互斥）
- 权威标签必须**双来源交叉验证**，且注明榜单年份；搜不到年份写「年份以官方最新榜为准」
- 非遗徽章必须带级别；「计划申遗」写「非遗申报中」
- 名人/媒体背书徽章 + 贴士栏注明具体人物、媒体与称号
- 菜系+档位徽章放店名旁（品类标注），与权威徽章分层不混排

### 分区规则（主线）

- **主线按区分章**：一个行政区一节，每区 10 家（酌情最多 15 家），按综合评级排序，各区不漏（含远郊）
- 每家店必须带**品类徽章**（粤菜/川菜/火锅/烧烤/早茶/糖水/小吃/潮汕/客家…标注主营品类）+ **档位徽章**（名店/高端/海鲜/连锁/街坊），一眼可辨
- 菜系只作店内标注，不再作分章主线；用户点名要某个品类（「只想看火锅」）时可按品类出筛选清单
- 某区搜不到过硬老店 → 只写有把握的，宁缺毋滥，并注明「该区本地硬店信息有限」（但区级模式最低 10 家，凑不到就扩宽品类）
- 非遗特色品类（凉茶/沙河粉/地方性小吃）也要有代表，不能只写菜

## 阶段 4：PDF 交付

1. 读取本 skill 目录 `assets/food_template.html`，按注释槽位填充（保留全部 CSS）
2. 结构固定：**封面 / ①城市总榜 TOP 10（双语）/ ②分区详解（每区 10-15 家）/ ③四大榜单速览（米其林星级榜·必比登推介·必吃榜·黑珍珠，完整名单附录）/ ④索引（人均价格带 + 场景）/ ⑤实用贴士 + Sources + 版本日志**；区级模式为 **封面 / ①该区前 30 家（最低 10 家）/ ②榜单速览 / ③实用贴士+Sources**
3. 封面：城市名（中英双语）+ 美食宣传语 + 数字条（总榜 10 家 / N 家推荐 / N 个区）+ `Designed by boai`；背景图用城市代表美食/地标图（Wikimedia Commons，走 Clash 代理 `-x http://127.0.0.1:7890` + User-Agent 头，base64 内嵌，来源写进 Sources；拿不到就删掉 img 与 grad 行）
4. **版本日志**：文末记录本版新增/修正/淘汰的店与规则变更；输出文件命名为 `{城市}美食推荐.pdf`，大改版另存 `{城市}美食推荐_{版本名}.pdf` **不覆盖旧版**（用户要对比时保留全部历史版本）

### 表格版式规范（用户指令 2026-09-08）

- 分区表 4 列：**排名（奖牌标号）｜店铺信息｜推荐菜｜上榜理由**
- **第二列「店铺信息」**：场景标签 + 店名 + 地址，下方依次换行 **☎ 电话 / 🕐 营业时间 / 人均**——品类徽章不进此列，把空间留给主要信息
- **推荐菜只列菜名 3-5 道，不标单价**（价格数据保留在源文件，需要时随时加回），列宽约 52mm 加宽处理
- **末列表头就叫「上榜理由」**（品类徽章在徽章分层组最前；评分/订位/排队/主厨/故事跟贴士留在末列，标签黑色加粗与正文区分）
- **店名只写中文，不加英文翻译**（封面/章节装饰性英文保留）
- **排名标号奖牌化**：前三名金/银/铜奥运奖牌质感（径向渐变 + 内阴影 + 金属环边），4 名起分区表用本区主题色、总榜用墨绿色；**圈内字号随底色深浅自适应**——深底白字、浅底黑字（番禺金/增城棕等浅色主题用黑字）
- **徽章分层组之间不加竖分隔线**，标签直接排列（防止多行换行时竖线挤在一起）
- **每区独立主题色**（标题文字、表头渐变、排名圆圈三处统一），11 区各不同色，分区表头渐变色阶
- **表格不加斑马纹**（无隔行底色），行与行之间仅靠细分隔线区分，保持列表感
- **人均只写价格区间**（¥30 以下 / ¥30-80 / ¥80-150 / ¥150-300 / ¥300-800 / ¥800+），不写单独人均数值；查不到写「以门店为准」
- 总榜表同构：排名｜店铺信息｜推荐菜｜上榜理由
5. 用 `scripts/html2pdf.sh` 转 PDF → `~/Documents/美食攻略/`
6. 校验：文件非空、页数合理（市级 15-60 页，区级 4-18 页）

## 质量红线

- ❌ 编造价格、榜单、人均——查不到标「以门店为准」
- ❌ 凭训练记忆写具体数字
- ❌ 只有店名没有地址/价格/人均
- ❌ 把博主单次推荐写成「本地人最爱」
- ❌ 榜单/标签无来源支撑，或权威徽章滥用（分层展示每层 ≤3 枚、合计 ≤6 枚）
- ❌ 文末没有 Sources 链接
- ❌ 用户有明确称呼偏好时不遵守（参考会话记忆）
